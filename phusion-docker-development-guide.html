Build Phusion with Docker

A repeatable workflow for building and actively developing the Linux SpatialExplorer Qt application without installing its large dependency stack directly on the host.

The mental model

buildimage-generic

A Dockerfile that produces the Ubuntu 26.04 resolute development environment, including Qt and the native dependencies.

phusion

The live source checkout. Docker bind-mounts it at /phusion, so edits and build artifacts stay on the host.

build-gui

The persistent CMake/Ninja build tree. The first build is large; later builds compile only what changed.

The container is the toolchain, not the source of truth.

Edit files normally under /home/mauricio/1playground/phusion. Start a disposable container whenever you need to configure, build, test, or run. Deleting the container does not delete the mounted source or build-gui/.

One-time host setup

You need Git, Docker Engine, an SSH key authorized for the private Phoenix GitLab repositories, substantial free disk space, and an x86-64 Linux desktop.

git --version
docker --version
docker run --rm hello-world
ssh-add -l
ssh -T git@gitlab.com
df -h /home/mauricio

If Docker reports permission denied, add the account to the Docker group and then log out and back in (or reboot):

sudo groupadd -f docker
sudo usermod -aG docker "$USER"
sudo systemctl daemon-reload
sudo systemctl restart docker
sudo reboot
Docker-group membership is effectively root-level access.

Only use it on a machine and account you trust. After reconnecting, rerun docker run --rm hello-world before attempting the long build.

Clone and prepare both repositories

mkdir -p /home/mauricio/1playground
cd /home/mauricio/1playground

git clone git@gitlab.com:phoenixlidar/buildimage-generic.git
git clone --recursive git@gitlab.com:phoenixlidar/phusion.git

cd buildimage-generic

cd ../phusion
git submodule update --init --recursive

If the repositories already exist, update deliberately rather than cloning again:

cd /home/mauricio/1playground/buildimage-generic
git status
git switch resolute
git pull --ff-only

cd /home/mauricio/1playground/phusion
git status
git pull --ff-only
git submodule update --init --recursive
Never pull or switch over work you have not reviewed.

Stop if git status shows source changes you do not recognize. Build directories and generated files may be untracked, but your edits must be understood before updating.

Correct the current Resolute permission typo

At the time this guide was written, the upstream Resolute Dockerfile ended with chmod -0644 /opt/setupenv.sh. The leading dash removes permission bits and produces a mode-000 file. Root-based CI masks the problem, but a safer UID-mapped developer container cannot source the environment and therefore cannot find Qt.

cd /home/mauricio/1playground/buildimage-generic
grep 'chmod.*setupenv' Dockerfile

# If the output says "chmod -0644", edit it to exactly:
# RUN chmod 0644 /opt/setupenv.sh

Once upstream contains the corrected line, no local edit is needed.

Build the Resolute dependency image

The Dockerfile fetches private repositories, so forward the already-loaded SSH agent into BuildKit:

cd /home/mauricio/1playground/buildimage-generic

DOCKER_BUILDKIT=1 docker build \
  --ssh default \
  --progress=plain \
  -t buildimage-generic:resolute-local \
  . 2>&1 | tee /tmp/buildimage-generic-resolute.log

This image is large and the initial build can take a long time. Docker caches successful layers; rerunning after a transient failure generally resumes from cached work.

docker image inspect buildimage-generic:resolute-local \
  --format 'id={{.Id}} size={{.Size}} bytes'

docker run --rm buildimage-generic:resolute-local \
  bash -lc 'test -r /opt/setupenv.sh && \
    test -f /opt/qt/6.11.1/gcc_64/lib/cmake/Qt6/Qt6Config.cmake && \
    echo "Resolute environment and Qt 6 are ready"'

Build the SpatialExplorer Qt GUI

This reproduces the important Linux CI settings: GCC 14, RelWithDebInfo, the Resolute dependency image, and the GeographicLib CMake module path. Mapping your host UID/GID prevents root-owned files in the bind-mounted checkout.

cd /home/mauricio/1playground/phusion

docker run --rm \
  --name spatialexplorer-gui-build \
  --user "$(id -u):$(id -g)" \
  -e HOME=/tmp/dev-home \
  -v "$PWD:/phusion" \
  -w /phusion \
  buildimage-generic:resolute-local \
  bash -lc '
    mkdir -p "$HOME"
    cmake -S spatialexplorer -B build-gui -G Ninja \
      -DCMAKE_BUILD_TYPE=RelWithDebInfo \
      -DCMAKE_CXX_COMPILER=g++-14 \
      -DCMAKE_C_COMPILER=gcc-14 \
      -DLICENSING_ALLOW_ALL_FEATURES=ON \
      -DCMAKE_MODULE_PATH=/usr/share/cmake/geographiclib
    cmake --build build-gui --target SpatialExplorer -j"$(nproc)"
  '

A successful initial build ends with Linking CXX executable SpatialExplorer. The result is:

/home/mauricio/1playground/phusion/build-gui/SpatialExplorer

RelWithDebInfo keeps debugging information, so the executable can be several gigabytes.

Your everyday edit–build loop

  1. Edit the Phusion source on the host.Use Neovim, Qt Creator, VS Code, or another editor in /home/mauricio/1playground/phusion.
  2. Run the incremental build.The existing build-gui/ tree retains configuration and object files, so there is no need to rebuild the dependency image unless its Dockerfile changed.
  3. Launch SpatialExplorer in the container.The binary depends on the image’s Qt and /opt libraries, so do not expect it to run directly on an unrelated host installation.
  4. Debug, adjust, repeat.Build output remains owned by your user because the container uses your numeric UID/GID.

Fast incremental build command:

cd /home/mauricio/1playground/phusion

docker run --rm \
  --name spatialexplorer-gui-build \
  --user "$(id -u):$(id -g)" \
  -e HOME=/tmp/dev-home \
  -v "$PWD:/phusion" -w /phusion \
  buildimage-generic:resolute-local \
  bash -lc 'mkdir -p "$HOME" && cmake --build build-gui --target SpatialExplorer -j"$(nproc)"'

Run the GUI on this Ubuntu desktop

This machine has an XWayland display at DISPLAY=:0. Pass the X11 socket and current Xauthority cookie into the container. Host networking supports services the application may contact, and extra shared memory helps Qt WebEngine.

cd /home/mauricio/1playground/phusion

docker run --rm -it \
  --name spatialexplorer-gui \
  --user "$(id -u):$(id -g)" \
  --network host \
  --shm-size=1g \
  -e HOME=/tmp/dev-home \
  -e DISPLAY="$DISPLAY" \
  -e XAUTHORITY=/tmp/.Xauthority \
  -v "$XAUTHORITY:/tmp/.Xauthority:ro" \
  -v /tmp/.X11-unix:/tmp/.X11-unix:rw \
  -v "$PWD:/phusion" \
  -w /phusion \
  buildimage-generic:resolute-local \
  bash -lc 'mkdir -p "$HOME" && exec ./build-gui/SpatialExplorer'

Keep the launching terminal open. Press Ctrl+C there to terminate the application if closing its window does not return to the prompt.

Open an interactive development shell

Use this when you want to explore dependencies, run CMake manually, inspect linked libraries, or use GDB:

cd /home/mauricio/1playground/phusion

docker run --rm -it \
  --name phusion-dev \
  --user "$(id -u):$(id -g)" \
  -e HOME=/tmp/dev-home \
  -v "$PWD:/phusion" \
  -w /phusion \
  buildimage-generic:resolute-local \
  bash

The image sets BASH_ENV=/opt/setupenv.sh, which adds Qt and the custom dependencies to paths such as CMAKE_PREFIX_PATH and LD_LIBRARY_PATH.

Troubleshooting

Qt6 cannot be found

Run docker run --rm buildimage-generic:resolute-local ls -l /opt/setupenv.sh. It must be readable, normally -rw-r--r--. Recheck the Resolute permission fix and rebuild the image.

Docker permission denied

Run id and confirm the docker group is present in the current login session. Group changes require a new login or reboot.

Private Git clone fails

Confirm ssh-add -l lists the Phoenix key, ssh -T git@gitlab.com succeeds, and the image build includes --ssh default.

GUI cannot connect to display

Confirm DISPLAY and XAUTHORITY are nonempty and that the Xauthority file exists. Log out/in if the desktop session changed and left a stale value.

Files are owned by root

Do not omit --user "$(id -u):$(id -g)". For an old root-owned build tree, repair ownership deliberately with sudo chown -R "$USER:$USER" build-gui.

A rebuild behaves strangely

First rerun CMake configuration. If a genuinely incompatible toolchain change requires a clean build, move the old build-gui aside rather than deleting it immediately.

Do not solve every problem with root.

Root inside a container can write root-owned files into bind mounts. It can also hide image permission bugs, as happened with setupenv.sh. Prefer your host UID/GID for development builds.

Success checklist

  • docker run --rm hello-world works without sudo.
  • buildimage-generic is on the resolute branch.
  • /opt/setupenv.sh is readable in the local image.
  • Phusion submodules are initialized recursively.
  • The build ends at [1493/1493] Linking CXX executable SpatialExplorer (the exact step count can change).
  • build-gui/SpatialExplorer exists and is owned by your user.
  • The X11-enabled Docker command opens the application on the host desktop.
